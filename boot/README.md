# Boot work

The A.119 boot image has been parsed and its ARM64 kernel, ramdisk, and base DTB extracted. The separate DTBO entry selected for RMX3231 is identified. See [the boot strategy](../docs/boot-strategy.md) for image layout and recovery constraints.

The first Linux userspace is an ARM64 BusyBox initramfs. Build it with `python3 scripts/build_initramfs.py`, then assemble the custom-key AVB-signed Android boot-image candidate with `python3 scripts/build_boot_image.py`. The builder requires the exact A.119 BOOT image at `firmware/extracted/boot/boot.img`, Python, OpenSSL, and network access to fetch the pinned AOSP AVB tool. It retains the stock kernel and complete base-DTB wrapper, updates the v2 legacy ID, replaces the ramdisk, signs a hash descriptor with a local RSA-4096 key, and writes a partition-sized 64 MiB result under ignored `builds/`.

The generated AVB signature and image hash are verified locally. The A.119 root vbmeta pins a different Realme key for the boot chain, so standard AVB behavior requires an unlocked bootloader to tolerate this key mismatch. That behavior is not verified on RMX3231. The candidate has not been booted. The phone's bootloader state, live partition size, and a tested recovery route are unknown. Do not flash it. The build output, public-key file, and private key are excluded from Git along with the proprietary stock image. Keep the private key secret.
